# BeMyVPN — Архитектура (финальная v1)

> Назначение проекта: **помочь людям попасть в свободный интернет** — туда, где
> есть свобода слова и доступ к информации. Это инструмент против цензуры и
> блокировок, целиком в рамках закона. Мы не строим ничего запрещённого: это
> тот же класс ПО, что и любой VPN.
>
> Этот документ — «конституция» проекта. Код следует ему. Он финальный для v1;
> но всё спроектировано так, чтобы **любую часть можно было легко заменить**
> (см. §16 «Что и где менять»).

---

## 0. Ключевые решения (одна таблица)

| Вопрос | Решение | Почему |
|---|---|---|
| Что это | Настоящий **VPN** (весь IP-трафик через TUN), P2P, host = выход в интернет | «Работает как ВПН» |
| Язык | **Rust** — одно ядро `bmv-core`, оболочки под платформы через FFI (UniFFI) | Лимит памяти iOS, скорость, одно переиспользуемое ядро |
| Крипто/маскировка | **Ось «протокол»** — выбор из плагинов, включая **без шифрования** | Твоё: «выбор и гибкость классная», «протоколы — класс» |
| Список хостов | **Каталог** в координаторе (публичные/приватные, страна, лимит) | Твоя идея, оставляем |
| Relay | ❌ **Убран** (пока). Только прямое P2P | Твоё: «не пускать трафик через relay пока что» |
| Amnezia (обычная) | ❌ **Убрана** | Твоё указание |
| Кто требует прав | **Только гость** (TUN). **Хост — без админ-прав** (userspace-стек + сокеты) | «На изи быть хостом» — реально на изи |
| NAT | STUN-пул (публичные + свой координатор) + hole-punching | Пробитие без relay |
| Координатор | Справочник + сигналинг + STUN. **В трафик не лезет.** Self-host 1 бинарём | Твой план |
| Конфиг | **ОДИН** плоский `bemyvpn.toml`, вся настройка там | «один, не закопанный» |
| Лицензия | Apache-2.0 (обсуждаемо) | OSS-дружелюбно |

## 1. Принципы

1. **Свобода доступа к информации.** Цель — свободный интернет, легально.
2. **Просто снаружи, строго внутри.** Пользователь видит тумблер и список хостов.
3. **Гибкость через плагины протоколов.** Хочешь скорость — `plain`. Хочешь стелс — `reality`. Выбор за тобой/конфигом.
4. **Не изобретать крипто.** Берём проверенные реализации (boringtun, sing-box), не пишем свой шифр.
5. **Одно ядро — много оболочек.** Вся логика в Rust-core; платформы = тонкие морды.
6. **Модульность как закон.** Каждый слой за `trait`; заменить реализацию = не трогать остальных.
7. **Один конфиг — один источник правды.** Никаких настроек, размазанных по коду.
8. **Хостом быть легко и безопасно-в-меру.** Без прав админа, с базовыми предупреждениями.

## 2. Три слоя (вся система)

Убрал лишнее: было 4 уровня — стало **3 чистых, независимых слоя**.

```
┌──────────────────────────────────────────────────────────────┐
│  ЗНАКОМСТВО (Discovery)                                        │
│  Найти пира и его адрес. Координатор (каталог+сигналинг) +     │
│  STUN-пул + hole-punching. Отдаёт «сырой путь» к пиру.         │
├──────────────────────────────────────────────────────────────┤
│  ПРОТОКОЛ (Protocol)  ← ОСЬ ГИБКОСТИ, плагины                  │
│  Берёт сырой путь и даёт ЗАШИФРОВАННЫЙ (или нет) дуплекс-канал.│
│  plain / wireguard / reality / webrtc / (свои). Выбор в конфиге│
├──────────────────────────────────────────────────────────────┤
│  ТУННЕЛЬ (Tunnel)  — сам VPN                                   │
│  ГОСТЬ: TUN → канал (весь IP-трафик ОС).                       │
│  ХОСТ: канал → userspace-стек → обычные сокеты в интернет.     │
└──────────────────────────────────────────────────────────────┘
```

Каждый слой знает только о соседнем через `trait`. Протокол не знает, что внутри — IP-пакеты. Туннель не знает, `plain` там или `reality`. Discovery не знает про шифрование.

## 3. Ось «Протокол» — центр гибкости (главный раздел)

Это ответ на «нужны ли протоколы или просто крипто»: **да, протоколы — как ось выбора.** Один интерфейс, много реализаций-плагинов. Каждый протокол сам решает, шифровать и как маскироваться. Пользователь (или авто-фолбэк) выбирает.

| Протокол | Шифрует? | Маскировка от DPI | Скорость | Когда |
|---|---|---|---|---|
| `plain` | ❌ нет | нет | 🟢 макс. | доверенная сеть, LAN, тесты, максимум скорости |
| `wireguard` | ✅ да | нет (детектится) | 🟢 высокая | свободные сети, где не режут WG |
| `webrtc` | ✅ да (DTLS) | как видеозвонок | 🟠 средняя | обход обычного DPI |
| `reality` | ✅ да | неотличимо от HTTPS к реальному сайту | 🟠 средняя | жёсткая цензура (сильнейший вариант) |

- **`plain`** — твоё «можно даже без шифрования». Полезно и как эталон скорости, и когда шифрование не нужно.
- **`reality`** на старте — через внешний бинарь `sing-box` (скачивается кнопкой, как xray в прототипе); нативный Rust-порт позже. `wireguard`/`webrtc`/`plain` — нативные.
- Новый протокол (shadowsocks, trojan, свой) = **один файл-плагин** + строчка в реестре. Ось расширяемая.

**Выбор протокола:**
- По умолчанию берётся из конфига (`default_protocol`).
- Можно переопределить в UI / флагом.
- **Фолбэк — внутренний, не в конфиге.** Если выбранный протокол не поднялся, ядро само тихо пробует следующий по встроенному порядку (`reality → webrtc → wireguard → plain`). Прозрачно для пользователя, конфиг не мусорится.

**Единый контракт (это и есть «стандарт»):**
```rust
#[async_trait]
pub trait Protocol: Send + Sync {
    fn name(&self) -> &str;
    fn encrypts(&self) -> bool;                 // для UI: показать замочек
    fn available(&self) -> bool;                // есть ли зависимости (напр. sing-box)

    /// Параметры, которые хост вшивает в код-приглашение (ключи/uuid/пароль).
    fn offer_params(&self) -> Params;

    /// Поднять канал поверх «сырого пути» (после hole-punch).
    async fn connect_host(&self, path: RawPath, sig: &Signal) -> Result<Box<dyn Link>>;
    async fn connect_guest(&self, path: RawPath, params: Params, sig: &Signal)
        -> Result<Box<dyn Link>>;
}

/// Готовый (возможно шифрованный) дуплекс байт-канал между пирами.
pub trait Link: AsyncRead + AsyncWrite + Send + Unpin {}
```
Хочешь заменить всю крипту — пишешь новый `impl Protocol`, остального кода не касаешься.

## 4. Знакомство и NAT (без relay)

- **STUN — пул**: публичные (Google/Cloudflare/…) **+ твой координатор как один из**, не единственный. Надёжнее и переживает блокировку одного домена.
- **Hole-punching**: пиры обмениваются кандидатами через координатор и пробивают прямой путь (UDP disco).
- **Relay убран.** Следствие честно: если у **обоих** симметричный NAT / мобильный CGNAT — прямое соединение не встанет. Решение — «хостом будь тот, у кого NAT попроще». Relay оставлен как **будущий опциональный модуль** (архитектура его допускает, код — нет).

## 5. Координатор (главный сервер)

Справочник, который свёл пиров и ушёл. **Не VPN-сервер, не в пути трафика, ключей не хранит.**

Делает:
1. **Каталог хостов** — анонсы: pubkey/id, кандидаты, метаданные (публичный/приватный, макс. гостей, страна IP, загрузка, версия). Гости берут список.
2. **Сигналинг** — свести гостя с хостом (обмен параметрами протокола и кандидатами).
3. **STUN** — как один из пула.
4. **Auth приватных** — проверить знание пароля (без передачи пароля), пропустить валидных.

Не делает: ❌ трафик, ❌ приватные ключи, ❌ relay.

Весь протокол — JSON-сообщения по **одному WebSocket** (`GET /v1/ws`, wss).
Клиент/хост подключаются К координатору (исходящее соединение проходит NAT),
ничего не открывая у себя. **Живость хоста = сам сокет**: закрылся → хост
мгновенно исчезает из каталога; «тихая смерть» ловится WS-пингом (~8с).

```
клиент → координатор                координатор → клиенту
─────────────────────               ──────────────────────
host    {анонс хоста}               hostok | error
watch   {country?}                  dirfull {version, hosts} + дельты:
                                    diradd/dirupdate/dirremove (пушем)
connect {host_id, candidates}       connected {endpoints}; хосту: guest {candidates}
newcode                             code {code, sig}   (сервер — источник кодов)
whoami                              ip {addr}
resolve {code}                      resolved {host?}   (в т.ч. скрытые)
```

Фолбэк сигналинга (если координатор заблокирован): публичная pub-sub доска (ntfy) из прототипа, либо ручной код вообще без сервера. Каталог при этом теряется, прямое соединение — нет.

## 6. Туннель — сам VPN (важная асимметрия)

**Гость (нужен TUN, значит права):**
```
приложения ОС → default route → TUN → читаем IP-пакеты → Protocol.Link (шифр) → хост
```
Весь трафик (TCP/UDP/DNS/QUIC) — автоматически, потому что это IP-уровень.

**Хост (НЕ нужен TUN, НЕ нужен админ):**
```
Link → userspace-стек (smoltcp) → терминируем TCP/UDP → обычные OS-сокеты → интернет
```
Хост не поднимает виртуальный интерфейс и не настраивает kernel-NAT. Он принимает IP-пакеты гостя, разбирает их пользовательским стеком (`smoltcp`) и открывает настоящие соединения обычными сокетами — как любое приложение. Отсюда:
- **«на изи быть хостом»** — запустил программу, без прав администратора;
- кросс-платформенно одинаково (Windows/Android/Linux/mac — везде просто сокеты);
- нет возни с ICS/iptables/RRAS.

Забота туннеля также: **DNS принудительно через туннель** (анти-утечка; opt-out только вручную), **IPv6** (вести или блокировать), **MTU** (считать корректно). Всё это — на стороне гостя, в `bmv-tunnel`.

> **Рубильника (kill-switch) НЕТ.** Ручка `kill_switch` в конфиге была объявлена и
> нигде не реализована — убрана, чтобы не обещать защиту, которой нет. Настоящий
> рубильник — это правила брандмауэра на десктопе (и застрявшее правило оставит
> машину вовсе без сети), а на Android приложение его в принципе не включит:
> «блокировать соединения без VPN» — системная настройка. Делать целиком и
> отдельным заходом либо не делать вовсе.

> Риск: userspace-стек сложнее и чуть медленнее kernel-forwarding. Это осознанный размен ради «хост без прав» и переносимости. `smoltcp` — зрелая Rust-реализация.

## 7. ОДИН конфиг — `bemyvpn.toml`

Единственный файл настроек клиента. Плоский, комментированный, лежит на виду.
Поиск по порядку: `--config PATH` → `$BEMYVPN_CONFIG` → рядом с бинарём `./bemyvpn.toml` → платформенный конфиг-каталог. Любого ключа может не быть — подставится дефолт из `bmv-config` (единственное место дефолтов в коде).

```toml
# ─────────────── BeMyVPN — единственный конфиг ───────────────
# Меняй смело. Чего нет — берётся разумный дефолт.

# Куда ходить за списком хостов и знакомством. НЕ захардкожено — меняй на свой.
coordinators = [
  "https://coord.bemyvpn.org",   # публичный по умолчанию
  # "https://my.coordinator.example",  # свой self-hosted
]

# Какой протокол связи использовать по умолчанию.
# Если он не поднимется — ядро САМО тихо попробует следующий (фолбэк внутренний,
# не настраивается здесь, чтобы не мусорить конфиг).
default_protocol = "reality"          # plain | wireguard | webrtc | reality

[guest]                                # когда я подключаюсь
# DNS всегда идёт через туннель (анти-утечка). Менять только если знаешь зачем.
dns          = "tunnel"                # tunnel (по умолч., принудительно) | 1.1.1.1 | system
ipv6         = "block"                 # route | block
auto_reconnect = true

[host]                                 # когда я раздаю интернет
enabled      = false
public       = false                   # показывать в публичном каталоге
password     = ""                      # непусто → приватный хост (PSK из пароля)
max_guests   = 4
country_hint = "auto"                  # для каталога; auto — по внешнему IP

# Параметры протоколов (нужны только выбранным). Пусто → сгенерится/дефолт.
[protocols.reality]
sing_box_path = ""                     # пусто → берём из bin/ (скачан кнопкой)
sni           = "www.mi.com"           # под какой сайт маскируемся (доступен широко: РФ/CN/мир)

[protocols.wireguard]
# ключи генерятся автоматически и хранятся в state, сюда лезть не нужно

[stun]
# Пусто → встроенный пул (публичные + координатор). Можно задать свой список.
servers = []

[log]
level = "info"                         # error | warn | info | debug
file  = "bemyvpn.log"
```

Ключевые ключи-«ручки», которые чаще всего дёргают: `coordinators`, `default_protocol`, `host.public`, `host.password`, `host.max_guests`. Всё в одном экране.

Координатор — отдельная программа с отдельным маленьким `coordinator.toml` (порт, домен, публичный/закрытый каталог). Это не «второй конфиг клиента», а конфиг сервера для тех, кто его поднимает.

## 9. Контракты-«стандарты» (чтобы не было копипаста)

Кроме `Protocol`/`Link` (§3):

```rust
// Туннель — две стороны за одним трейтом.
#[async_trait] pub trait Tunnel {
    async fn run_guest(&self, link: Box<dyn Link>) -> Result<()>;   // TUN ↔ link
    async fn run_host (&self, link: Box<dyn Link>) -> Result<()>;   // link ↔ сокеты
}

// TUI — «на изи делать афигенные менюшки» без повтора кода.
pub trait Screen { fn view(&self, f: &mut Frame); fn key(&mut self, k: Key) -> Nav; }
pub struct Menu { /* стрелки/Enter/Esc — реализовано один раз, юзают все экраны */ }

// Публичный фасад для всех оболочек — платформы зовут только это.
impl BmvEngine {
    fn from_config(cfg: Config) -> Self;
    async fn start_guest(&self, host: HostRef) -> Session;   // host по коду или из каталога
    async fn start_host (&self) -> HostHandle;
    async fn directory(&self, filter: Filter) -> Vec<HostInfo>;
    fn on_event(&self, cb: impl Fn(Event));                  // статусы для UI
}
```
`BmvEngine` — единственная дверь для Kotlin/Swift/CLI/GUI. Новая платформа = новая морда к тому же фасаду.

## 10. UX (простота = фича)

**Стать хостом:** тумблер «Раздавать» → (опц. «Приватный» + пароль). Без прав админа. Готово.
**Гость по каталогу:** список (страна/загрузка/замочек публичный-приватный) → выбрал → «Подключиться» → (приватный: пароль).
**Гость по коду:** вставил `BMV1:<id>#<отпечаток>` → подключился (отпечаток защищает от подмены).
Под капотом (не видно): координатор → обмен параметрами → hole-punch → протокол поднимает канал → авто-реконнект.

## 11. Безопасность (в меру)

- **Трафик**: шифрует выбранный протокол (`wireguard`/`webrtc`/`reality`). `plain` — осознанно без шифра.
- **Подмена хоста**: отпечаток ключа/параметров хоста в коде и каталоге → гость проверяет. Trust-on-first-use.
- **Приватные хосты**: пароль → Argon2id → PSK/секрет протокола.
- **Координатор скомпрометирован**: максимум врёт в каталоге; трафик не видит.
- **НЕ делаем**: свой PKI, свой шифр, обязательные аккаунты.
- **Риск хоста (не забыть)**: трафик выходит с IP хоста → предупреждение при включении + (позже) простые фильтры/лимиты. Публичный хост может видеть НЕ-HTTPS трафик гостя на выходе → советуем HTTPS/DoH.

---

## 12. Устойчивость к блокировкам

Несколько адресов координатора (перебор) · всё по 443 · протоколы `reality`/`webrtc` для данных · фолбэк сигналинга на pub-sub доску · ручной код без сервера · STUN-пул. Блокировка одного узла ≠ смерть сети.

## 13. Open-source и свой сервер

- Координатор — один статический бинарь: `docker run bemyvpn/coordinator` или `./coordinator --config coordinator.toml`.
- Клиент: `coordinators = ["https://my..."]` в конфиге. **Адрес нигде не захардкожен.**
- Лицензия: **Apache-2.0** (обсуждаемо, альтернатива BSD-3).
- `docs/SELF_HOSTING.md` — поднять свой координатор за 10 минут (позже).

## 14. Платформы (P0 = Windows + Android)

| Платформа | TUN (только гость) | Хост | Приоритет |
|---|---|---|---|
| **Windows** | Wintun | userspace-стек, без админа | **P0** |
| **Android** | VpnService (fd) | userspace-стек | **P0** |
| Linux | /dev/net/tun | userspace-стек | P1 |
| iPhone | NetworkExtension | userspace-стек | P2 |
| macOS (ARM) | utun / NE | userspace-стек | P2 (dev-машина) |

Ядро (`bmv-core` и слои) — платформо-независимо, разрабатывается на dev-Mac, тестируется на loopback + локальный TUN. Платформенный TUN нужен только гостю.

## 15. Дорожная карта

- **Фаза 0 — Каркас.** Workspace, `bmv-core`, `bmv-config` (один toml), `bmv-protocol` (`plain` + `wireguard`), `bmv-net` (STUN+hole-punch), `bmv-signal` (мин. координатор), `bmv-tunnel` (guest-TUN + host-netstack). Цель: два пира, туннель по коду, реальный сайт открывается.
- **Фаза 1 — MVP: Windows + Android.** Wintun + VpnService, каталог хостов, `webrtc`-протокол, DNS. Цель: рабочий VPN на P0-платформах.
- **Фаза 2 — Жёсткая цензура + Linux.** `reality` (sing-box), авто-фолбэк протоколов, pub-sub фолбэк, приватные хосты. Linux-клиент/хост.
- **Фаза 3 — Apple.** iOS/macOS через `bmv-ffi`, Tauri GUI, подготовка к сторам.
- **Фаза 4 — Экосистема.** Self-hosting docs, авто-апдейт, CI-подпись, (опц.) relay-модуль, учёт трафика хоста.

## 16. Что и где менять (карта модульности — прямо под твой запрос)

| Хочу поменять… | Трогаю только… | Не трогаю |
|---|---|---|
| Настройку (адрес сервера, протокол, лимиты) | `bemyvpn.toml` | код |
| Добавить/сменить протокол шифрования | новый файл в `bmv-protocol/` + строка в `registry.rs` | ядро, туннель, UI |
| Другой координатор/каталог | `coordinators` в конфиге | код |
| Логику знакомства/NAT | `bmv-net` | протоколы, туннель |
| Поведение VPN (DNS, routing, MTU) | `bmv-tunnel` | протоколы, сеть |
| Дефолтные значения | `bmv-config` (одно место) | везде |
| Внешний вид меню/экрана | `bmv-tui` (виджеты) / `apps/gui` | ядро |
| Новую платформу | новая папка в `apps/` + `bmv-ffi` | всю логику (она в core) |
| Вернуть relay | новый модуль-протокол `relay` | остальное |

Принцип: **изменение живёт в одном месте.** Слои развязаны трейтами, настройки — в одном toml, дефолты — в одном крейте.

## 17. Решения (все приняты — «точка»)

1. ✅ Лицензия — **Apache-2.0**.
2. ✅ Знакомство — **сначала «по коду» (Фаза 0)**, публичный каталог — Фаза 1.
3. ✅ `reality` — через внешний `sing-box`-бинарь на старте, нативный Rust позже.
4. ✅ Хост — **userspace-стек `smoltcp`** (без прав админа) как основной путь.
5. ✅ DNS — **принудительно через туннель** (анти-утечка), opt-out только вручную.
6. ✅ Фолбэк протокола — **внутренний** (`reality → webrtc → wireguard → plain`), не в конфиге.
