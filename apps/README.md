# Структура приложений BeMyVPN

Короткий ответ на «нужны ли отдельные папки под каждую ОС»: **нет — 5 папок с
дублированным кодом были бы ошибкой.** Всё ядро VPN (`crates/` + `vendor/ipstack`)
— ОДНО, компилируется нативно под каждую платформу. Приложения — это тонкие
«оболочки» поверх ядра. Одна оболочка часто закрывает несколько ОС:

| Папка | Платформы | Технология | Почему так |
|---|---|---|---|
| `apps/ios` | **iOS + macOS** | Swift / SwiftUI + Network Extension | Это ОДИН и тот же код. macOS = **Mac Catalyst** (пересборка того же iOS-приложения в нативный Mac-app). Отличаются лишь настройки сборки (Catalyst-entitlements для песочницы). Логотип, экраны, туннель — общие. |
| `apps/bmv-gui` | **Windows + Linux** | Rust + Slint | Один Slint-код компилируется нативно под Win и Linux. (macOS тоже может, но там лучше Catalyst — поэтому десктоп-Slint = для Win/Linux.) |
| `apps/android` | **Android** | Kotlin / Jetpack Compose + JNI | Своя платформа, свой UI-фреймворк — отдельная оболочка. |
| `apps/bmv-cli` | Linux / macOS / Windows (терминал) | Rust + ratatui | Клиент/хост/координатор в одном бинаре `bemyvpn` (TUI без аргументов). |

## Принцип
- **Ядро одно** (`crates/bmv-*`, `server/coordinator`, `vendor/ipstack`). Логику
  подключения, шифрование, реконнект, BYE, счётчик гостей — не дублируем.
- **iOS и macOS — один код** (Catalyst). Заводить `apps/macos` с копией кода —
  значит поддерживать два одинаковых приложения. Не нужно.
- **Win/Linux — один код** (Slint). Аналогично.
- Оболочка = только «мост» UI ↔ ядро: у iOS/macOS через C-ABI (`bmv-ffi`), у
  Android через JNI (тонкий `apps/android/rust` поверх того же `bmv-ffi`), у
  десктопа Slint линкует ядро напрямую.

## Где что менять
- Общее поведение VPN (как считаются гости, как рвётся туннель, реконнект) →
  `crates/` (одно место, работает везде).
- Вид/экраны конкретной платформы → её папка выше.
- Логотип «Звено» → `brand/` (канон), оттуда в иконки платформ.
