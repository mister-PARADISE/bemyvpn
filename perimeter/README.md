# Периметр

Панель для аудита сайтов по согласию владельца, в стиле терминала. В ней хранятся цели (сайты) и их хосты, модули разведки запускаются в один клик с живым выводом, рядом — свои прокси. Клиенты и счета появятся позже отдельным расширением.

## Запуск

| Система | Команда |
|---|---|
| macOS, Linux | `./start.sh` |
| Windows | `start.bat` |

При первом запуске скрипт сам найдёт подходящий Python (3.11 или новее — `python3.13`, `3.12`, `3.11`, `python3`), создаст окружение и поставит зависимости, затем панель откроется в браузере и попросит придумать имя и пароль администратора. Если окружение когда-то собралось старым Python (на macOS по умолчанию стоит 3.9) или установка оборвалась, скрипт пересоберёт его сам. Свой Python: `PYTHON=/путь/к/python3.13 ./start.sh`.

- Адрес: `http://127.0.0.1:8710`, слушает только этот компьютер.
- Данные (база, ключ сессий, свои плагины) лежат в папке `data/` рядом.
- Другой порт: `./start.sh --port 9000`. Без браузера: `--no-browser`.
- Если забыли пароль: `.venv/bin/python -m perimeter reset-password admin`.

Нужен Python 3.11 или новее.

## Что уже есть

| Раздел | Что делает |
|---|---|
| Вход | Как в консоль: ASCII-лого, `perimeter login:`, Enter — к паролю, пароль при вводе не отображается |
| Обзор | Как htop: живые полосы cpu, ram, swap, disk, нагрузка, аптайм машины и сколько ест сама панель. Ниже «Панель» — строки от расширений (цели, запуски, прокси, модули) и журнал |
| Прокси | Свои прокси списком в любом формате, проверка: жив ли, какой IP на выходе, страна, провайдер, отклик |
| Модули | Каталог инструментов по группам: пассивные и активные, какие данные принимают и выдают, на чём построены и что построено на них. Вкладка «Данные» — базы модулей, которые обновляются сами: когда обновлялись, что изменилось, следующее обновление, журнал, кнопка «обновить сейчас» |
| Цели | Домен (кириллица и `www` приводятся к одному виду) и его **хосты**. В списке у каждого сайта — адрес и провайдер, замечания (`[!] 1 [~] 3`), когда проверяли. Страница цели — ниже |
| Запуски | Все запуски модулей: очередь, идёт, готово, ошибка, пропущен. Живой вывод, остановка, повтор |
| Журнал | Каждое действие: кто, что и когда. Записи остаются после удаления объекта |
| Настройки | Формы строятся из описаний полей: название, часовой пояс, цвет терминала, плотность, пароль |

Быстрые клавиши: `/` или `Ctrl K` — поиск по всему (цели, настройки, прокси и находки: «где этот IP?»), `Ctrl B` — свернуть панель.

Оформление — как в терминале, без свечения, рамок и коробок: почти чёрный фон, зелёный люминофор (есть янтарный и бирюзовый), шрифт JetBrains Mono лежит в самой панели. Разделы отбиваются заголовком с линией, над заголовком страницы — приглашение `admin@perimeter:~/цели$`, выбранный пункт меню — инверсией, внизу строка состояния как в tmux (окна `0:обзор 1:цели*…`, сервер, пользователь, часы), кнопки — `[ Сохранить ]`, уведомления — `[ok] …`. Полосы ЭЛТ-монитора включаются в настройках. На телефоне таблицы складываются в карточки, полосы монитора подстраиваются под ширину, ни одна страница не вылезает за экран.

## Страница цели

Сверху — оглавление, оно едет вместе со страницей и подсвечивает раздел, который сейчас на экране. Рядом с пунктами — сколько там всего, красным — если есть серьёзное.

| Раздел | Что там |
|---|---|
| Сводка | Главное одним взглядом, по пяти группам. **Сеть**: адреса, хостинг (компания, AS, страна), CDN, обратное имя, пинг. **Сайт**: ответ, заголовок страницы, https, уводит ли http на https, HSTS, защитные заголовки, cookie, сертификат (кем выдан, сколько жить, версия TLS). **DNS и почта**: у кого DNS, DNSSEC, CAA, у кого почта, SPF, DMARC. **Снаружи**: открытые порты (опасные красным), закрывшиеся с прошлого раза, соседи. **Программы и уязвимости**: что работает и каких версий, сколько уязвимостей по уровням, сколько уже используют в атаках, у каких веток кончилась поддержка, что до какой версии обновить. Каждая строка знает свой модуль: пока он не запускался, вместо значения — кнопка «▶ модуль» |
| Замечания | Что плохо и что с этим делать, самое серьёзное сверху: `[!]` плохо, `[~]` стоит поправить, `[i]` к сведению. Одно замечание на нескольких именах (общий сертификат) — одной строкой; у программы уязвимости и поддержка ветки — тоже одним замечанием. Нажатие ведёт к месту в структуре или к программе в «Уязвимостях» |
| Уязвимости | По каждой программе: сколько и каких, где работает, до какой версии обновиться, чтобы закрыть всё известное. Рядом с программой — поддержка её ветки («ветка 8.1 без поддержки с 2025-12-31», «в ветке 6.4 есть 6.4.14»). В таблице — номер (ссылка на NVD), оценка CVSS, вероятность атаки (EPSS), версия с исправлением, признаки «новая», «в атаках» (CISA KEV), «вымогатели», «эксплойт», «нет исправления» и суть. Самые опасные — сверху; раскрыта самая опасная программа, у остальных — первые 10 и «ещё N». Программа без известных CVE, но без поддержки, тоже здесь |
| Структура | Дерево: имена → адреса → порты → что на них отвечает → какие там программы (`CVE 12` у уязвимых). У адреса — провайдер, обратное имя, пинг, CDN; у порта — сервис, ответ сайта, заголовок, сертификат или баннер. Ниже — соседи по сети, имена из сертификатов, DNS. Адрес или порт копируется нажатием |
| Модули | По группам (DNS, сеть, веб): запуск в один клик, параметры, последний результат. Консоль показывает всю цепочку подряд, с разделителями `── [3/13] Почта ──`, статусы в списке обновляются на ходу |
| Найдено | Всё, что нашли модули, таблицами по видам — ничего не теряется |
| Хосты, Можно добавить, История | Справа: что входит в цель, что модули предлагают добавить, журнал по цели |

## Хосты

Хосты — что входит в цель. Основной домен входит сам, вместе с поддоменами. Остальное добавляется одной строкой справа на странице цели:

```
api.example.com 203.0.113.10 10.0.0.0/24 -pay.example.com
```

- через пробел или запятую: домены, IP, подсети;
- `-адрес` (или `!адрес`) — не трогать: модули туда не пойдут, даже если адрес входит в цель;
- лишнее панель отсеет сама: что уже входит, повторы, непонятное — скажет, что именно;
- `?` — проверить, входит ли адрес в цель и почему.

Модули сами находят новые имена и адреса цели (из сертификатов, редиректов, соседей по сети) и показывают их в блоке «Можно добавить»: `+` — добавить в хосты, `×` — скрыть.

## Модули разведки

Один модуль — один вопрос.

| Модуль | Вид | Вопрос |
|---|---|---|
| Адреса | пассивный | В какие IP смотрят имена цели: A, AAAA, цепочка CNAME. Если имя больше не указывает на старый адрес, модули его больше не трогают — там может быть уже чужой сервер |
| Провайдер | пассивный | Чья сеть у адресов: AS, компания, префикс, страна (Team Cymru по DNS). Узнаёт CDN — у CDN порты не сканируются |
| Обратные имена | пассивный | Как адреса называют себя (PTR): часто это имя сервера у хостинга |
| DNS-зона | пассивный | Кто держит DNS (NS), SOA, подписана ли зона (DNSSEC), кому разрешено выпускать сертификаты (CAA) |
| Почта | пассивный | Куда приходит почта (MX, чей сервис) и защищён ли домен от поддельных писем: SPF и DMARC |
| Соседи по подсети | пассивный | Обратные имена соседних адресов (/28, /26, /24, не шире сети провайдера). Похожие на имена цели — в «Можно добавить» |
| Пинг | активный | Отвечают ли адреса и как быстро: TCP на 443, а если закрыт — на 80; потери и разброс |
| Ответ сайта | активный | Код, сервер, заголовок страницы, редиректы (за пределы цели не ходит), уводит ли http на https, HSTS, защитные заголовки, флаги cookie |
| Сертификат | активный | Проходит ли проверку (и если нет — почему, по-русски), кем выдан, сколько осталось, версия TLS и шифр; другие имена из сертификата — в подсказки |
| Открытые порты | активный | Порты по набору (топ-100, опасные, веб, свой список) и что на них отвечает: баннер, версия. Помечает то, что не должно торчать наружу (базы, RDP, Redis…), и порты, которые закрылись с прошлого раза |
| Технологии | активный | Какие программы и каких версий работают: веб-сервер, язык, CMS с плагинами и темами, панели, базы, почта, SSH, FTP, JS-библиотеки. Около 110 программ; источники — приветствия сервисов, заголовки, cookie, страница и страница ошибки, пара десятков служебных адресов, где программы сами называют версию, начала JS-файлов, `readme.txt` плагинов WordPress и `style.css` тем |
| Уязвимости (CVE) | пассивный | Какие известные уязвимости есть у найденных версий. Сайт не трогает — спрашивает открытые базы (ниже) |
| Поддержка версий | пассивный | Поддерживается ли ещё ветка каждой программы: до какого числа для неё выпускают исправления безопасности, последний выпуск ветки, актуальная ветка (endoflife.date, 63 программы). Ветку без поддержки не чинят вовсе — новые дыры в ней остаются навсегда |

**Зависимости.** Модуль говорит, на чём он построен (`ModuleSpec.needs`): «Открытые порты» — на «Адресах» и «Провайдере». Нажали ▶ у портов на новой цели — движок сам поставит цепочку «Адреса → Провайдер → Открытые порты». Свежие результаты не повторяются; устаревшие (основу обновили позже, находки очистили) — повторяются, как в make. Если основа в цепочке упала, всё, что на ней построено, помечается «пропущен», а не гоняется впустую. «Остановить всё» гасит цепочку целиком.

«Запустить всё» — одна цепочка: сначала пассивные, потом активные, зависимости раньше. У каждого модуля есть `[параметры]`. DNS-серверы и тайм-ауты — в «Настройки → Разведка».

## Уязвимости

Модуль «Уязвимости (CVE)» берёт из базы **всё** по программе, а версию сверяет сам — так находятся и точные совпадения («OpenSSH 9.6p1»), и диапазоны («все версии с 8.5 до 9.8»). Версии сравниваются по-человечески: `9.6p1` новее `9.6`, `2.0.0-rc1` старше `2.0.0`, `1.0.2k` старше `1.0.2u`.

| База | Что даёт |
|---|---|
| NVD (NIST) | Все CVE программы с диапазонами уязвимых версий, оценкой CVSS, типом ошибки (CWE), ссылками на эксплойты и исправления |
| WPVulnerability | Плагины и темы WordPress по названию — в NVD у них чужие имена, а у свежих уязвимостей их нет вовсе. Внутри — данные Wordfence, Patchstack, WPScan. Повторы одной дыры из разных источников сводятся в одну строку |
| CISA KEV | Какие уязвимости уже используют в настоящих атаках (и вымогатели) — такие идут первыми |
| FIRST EPSS | Вероятность, что уязвимость начнут использовать в ближайший месяц |

- Базы хранятся в `data/vulndb/` и обновляются сами (ниже): десятая цель с тем же nginx базы заново не спрашивает.
- Уязвимость, которая появилась с прошлой проверки программы, помечается «новая» — неделю она видна в разделе и в итоге запуска.
- NVD без ключа отвечает 5 раз за 30 секунд — первая проверка идёт несколько минут. Бесплатный ключ (nvd.nist.gov/developers/request-an-api-key) в «Настройки → Уязвимости» ускоряет её в 10 раз.
- Неточную версию («nginx» без номера, «PHP 8») не сверяем — будет куча ложных совпадений; такие программы перечислены отдельно.
- Сборки Ubuntu, Debian, RHEL помечаются: дистрибутивы переносят исправления без смены версии, поэтому такие совпадения надо сверить с их бюллетенями.
- Уязвимость, которой больше нет (программу обновили), помечается закрытой, а программа — «больше не видно».

## Данные модулей обновляются сами

Каждый день в NVD появляются новые CVE, CISA добавляет уязвимости, которые начали использовать в атаках, EPSS пересчитывает вероятности, выходят новые версии программ. Панель следит за этим сама:

| Данные | Что обновляется |
|---|---|
| NVD | Только изменения с прошлого раза (`lastModStartDate`): новые CVE и уточнённые версии по программам, которые есть на целях. Обычно один короткий запрос на программу, а не перекачка сотен записей |
| База WordPress | Плагины и темы, найденные на целях |
| CISA KEV | Весь каталог (в атаках) |
| EPSS | Оценки всех уязвимостей на целях |
| Сроки поддержки | Ветки программ из endoflife.date |

- Раз в сутки (меняется в «Настройки → Уязвимости»). Не получилось — повтор через полчаса.
- После обновления, которое что-то изменило, **пассивные** модули сами перепроверяют цели, где уже работали: к сайтам они не обращаются, только сверяют найденное со свежими базами. Новая уязвимость в старой версии всплывёт сама, с пометкой «новая» и строкой в журнале. Активные модули (порты, технологии) по расписанию не запускаются никогда.
- Всё видно в «Модули → Данные»: когда обновлялось, сколько записей и что изменилось, когда следующее, журнал последнего обновления, кнопка «обновить сейчас». На обзоре — строка «данные модулей».
- Выключить расписание или перепроверку — «Настройки → Данные модулей».

Свой источник расширение описывает одним `Feed` — расписание, состояние и перепроверку панель берёт на себя:

```python
async def refresh(job):                       # job.log, job.setting, job.data_dir
    job.log("[*] качаю список выходов Tor")
    ...
    job.items, job.changed = 1250, 7          # сколько всего и сколько изменилось
    return "записей 1250, новых 7"

ctx.feeds.add(Feed("tor.exits", "Выходы Tor", refresh, source="check.torproject.org",
                   every=6, modules=("asn",)))  # раз в 6 ч; после — перепроверить цели «Провайдером»
```

## Пассивные и активные модули

Каждый модуль в паспорте указывает свой вид:

- **пассивный** — берёт данные из открытых источников (WHOIS, DNS, логи сертификатов) и к сайту не обращается;
- **активный** — шлёт запросы сайту (порты, заголовки, файлы), но только к хостам цели.

Хосты проверяет ядро, а не автор модуля: любое соединение идёт через `run.connect`, и адрес вне цели отклоняется («не входит в цель»). Подробнее:

- IP, в который указывает имя цели, входит в цель сам — пока это имя входит в цель: исключили имя — исключён и его адрес;
- имя, на которое больше не указывает адрес, «уходит»: старый IP модули больше не трогают;
- адрес CDN (Cloudflare и т.п.) — чужая инфраструктура: туда можно только как на сайт, порты 80 и 443, порты сканировать нельзя;
- пока «Провайдер» не проверил сеть адреса, на него тоже только 80 и 443 — вдруг это CDN;
- соединение по имени проверяется дважды: имя — по хостам, а IP, в который оно разрешилось, — по тем же правилам;
- в хосты не добавить общий домен (`github.io`, `co.uk`…) и сеть шире /16 — это почти наверняка чужое или опечатка;
- соседи по подсети — не цель: их модуль только смотрит в DNS и к ним не подключается;
- редиректы за пределы цели не открываются;
- пассивному модулю подключаться нельзя вообще.

Активный модуль не уйдёт на чужой CDN или платёжный шлюз, даже если наткнётся на них по пути. Согласие владельца вы проверяете сами до того, как добавить сайт.

## Как устроено

Всё, кроме ядра, — расширения. Встроенные лежат в `perimeter/extensions/`, свои — в `data/plugins/<имя>/__init__.py`. И те и другие устроены одинаково: функция `setup(ctx)` регистрирует нужное.

```python
def setup(ctx):
    ctx.pages.add(Page("reports", "Отчёты", "/reports", icon="file"))   # пункт меню
    ctx.add_router(router)                                               # страницы FastAPI
    ctx.widgets.add(Widget("risk", "Риски", "reports/_widget.html"))    # блок на «Обзоре»
    ctx.stats.add(Stat("proxies", "прокси", count_alive))           # строка в «Панели» на обзоре
    ctx.add_slot("target.main", Slot("scans", "reports/_scans.html",     # блок в чужой странице
                                     nav="сканы"))                       # и пункт в её оглавлении
    ctx.settings.section(SettingsSection(id="shodan", title="Shodan",    # раздел настроек
        group="Модули", fields=(f.secret("api_key", "Ключ API"),)))
    ctx.modules.add(Whois)                                               # инструмент
    ctx.feeds.add(Feed("whois.tlds", "Серверы WHOIS", refresh, every=168))  # данные, которые обновляются сами
    ctx.events.on("run.done", notify)                                   # реакция на событие
    ctx.hook("target.before_delete", check)                              # право вето: вернуть строку-причину
    ctx.hook("targets.columns", columns)                                 # колонки в списке целей
    ctx.search(find_reports)                                             # результаты в поиске
    ctx.services["proxies"].pick()                                      # общие объекты других расширений
```

Модуль — класс с паспортом и одной функцией:

```python
class Banner(Module):
    spec = ModuleSpec(id="banner", title="Баннер", kind=Kind.ACTIVE, consumes=("ip",), produces=("port",),
                      needs=("resolve", "asn"),                       # запустятся первыми, если нужно
                      params=(f.integer("port", "Порт", default=22),), timeout=60)

    async def run(self, run):
        for ip in run.assets("ip"):
            reader, writer = await run.connect(ip["value"], run.params["port"])  # вне цели — отказ
            line = (await reader.readline()).decode(errors="replace").strip()
            run.log(f"[+] {ip['value']}  {line}", "found")
            await run.emit("port", f"{ip['value']}:{run.params['port']}", banner=line)
```

`run.log` пишет в консоль, `run.progress` двигает полосу, `run.emit` сохраняет находку (повтор обновит старую), `run.assets` отдаёт то, что нашли другие модули. Остановка, тайм-аут и ошибки — забота движка.

- Шаблоны из папки `templates/` расширения подключаются сами.
- Блок с `nav` попадает в оглавление страницы (якорь — его id). Число рядом с пунктом блок отдаёт сам: `nav_count` в своих данных, цвет — `nav_tone` (`err`, `warn`, `ok`). Если данные блока — `None`, блок и пункт не показываются.
- Если `setup` упал, всё, что расширение успело зарегистрировать, откатывается. Ошибка видна в «Модули → Расширения».
- Поля (`core/fields.py`) общие для настроек, форм и параметров модулей: одно описание даёт форму, проверку ввода и значение по умолчанию.


## Безопасность самой панели

- Пароль хранится как scrypt-хэш, после 5 неудачных входов вход блокируется на 5 минут.
- Смена пароля завершает все остальные входы.
- Все формы защищены CSRF-токеном.
- Заголовки CSP, `X-Frame-Options`, `no-store` для страниц; внешние скрипты и шрифты не грузятся.
