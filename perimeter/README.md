# Периметр

Панель для аудита сайтов по согласию владельца. Здесь ведутся клиенты, ручные счета и сайты (цели), у каждого сайта есть границы проверки и отметка о разрешении владельца. Инструменты подключаются модулями.

Стиль — как у TG4WORK: светлая и тёмная тема (по системе), кнопки-иконки, сворачиваемая панель слева, на телефоне всё складывается в карточки.

## Запуск

| Система | Команда |
|---|---|
| macOS, Linux | `./start.sh` |
| Windows | `start.bat` |

Первый запуск сам создаст окружение и поставит зависимости, дальше панель сразу откроется в браузере. Затем панель попросит придумать имя и пароль администратора.

- Адрес: `http://127.0.0.1:8710`, слушает только этот компьютер.
- Данные (база, ключ сессий, свои плагины) лежат в папке `data/` рядом.
- Другой порт: `./start.sh --port 9000`. Без браузера: `--no-browser`.
- Забыли пароль: `.venv/bin/python -m perimeter reset-password admin`.

Нужен Python 3.11 или новее.

## Что уже есть

| Раздел | Что делает |
|---|---|
| Обзор | Виджеты: ждущие оплаты и просроченные счета, кончающиеся оплаты, цели без разрешения, последние действия |
| Клиенты | Карточка: контакты (копируются кликом), статус, «оплачено до», сайты, счета, история |
| Счета | Выставили → «Оплачен» одной кнопкой → «оплачено до» у клиента продлевается само |
| Цели | Домен (кириллица и `www` нормализуются), границы: доп. домены, IP, подсети, исключения. Проверка «входит ли адрес» |
| Разрешение | Код для TXT-записи, файла или meta-тега, либо договор. Отмечается с подтверждением и сроком; истёкшее видно сразу |
| Модули | Каталог инструментов: пассивные и активные, какие данные принимают и выдают, кто кого может продолжить |
| Журнал | Каждое действие: кто, что, когда. Записи не пропадают при удалении объектов |
| Настройки | Формы строятся из описаний полей: название, часовой пояс, валюта, тема, акцент, плотность, пароль |

Быстрые клавиши: `/` или `Ctrl K` — поиск по всему, `Ctrl B` — свернуть панель.

## Главный предохранитель

У каждого модуля в паспорте указан вид:

- **пассивный** — берёт данные из публичных источников (WHOIS, DNS, логи сертификатов) и к сайту не обращается;
- **активный** — шлёт запросы сайту (порты, заголовки, файлы).

Активный модуль запустится только для цели с действующим разрешением и только в её границах. Проверку делает ядро, а не автор модуля, поэтому новый модуль не может её обойти.

## Как устроено

Всё, кроме ядра, — расширения. Встроенные лежат в `perimeter/extensions/`, свои — в `data/plugins/<имя>/__init__.py`. Устроены одинаково: функция `setup(ctx)` регистрирует то, что нужно.

```python
def setup(ctx):
    ctx.pages.add(Page("reports", "Отчёты", "/reports", icon="file"))   # пункт меню
    ctx.add_router(router)                                               # страницы FastAPI
    ctx.widgets.add(Widget("risk", "Риски", "reports/_widget.html"))    # карточка на «Обзоре»
    ctx.add_slot("target.main", Slot("scans", "reports/_scans.html"))    # блок в чужой странице
    ctx.settings.section(SettingsSection(id="shodan", title="Shodan",    # раздел настроек
        group="Модули", fields=(f.secret("api_key", "Ключ API"),)))
    ctx.modules.add(Whois)                                               # инструмент
    ctx.events.on("target.authorized", notify)                          # реакция на событие
    ctx.hook("client.before_delete", check)                              # право вето
    ctx.search(find_reports)                                             # результаты в поиске
```

- Шаблоны из папки `templates/` расширения подключаются сами.
- Если `setup` упал, всё, что расширение успело зарегистрировать, откатывается. Ошибку видно в «Модули → Расширения».
- Поля (`core/fields.py`) общие для настроек, форм и параметров модулей: одно описание даёт форму, проверку ввода и значение по умолчанию.

```
perimeter/
  core/        реестры, события, поля, настройки, границы, контракт модулей, загрузчик расширений
  web/         сборка приложения, вход, CSRF, шаблоны и дизайн-система (static/app.css, app.js)
  extensions/  обзор, клиенты и счета, цели, каталог, журнал, настройки
tests/         51 тест: ядро, вход и защита, клиенты, счета, цели, расширения
```

## Безопасность самой панели

- Пароль хранится как scrypt-хэш. После 5 неудачных входов вход блокируется на 5 минут.
- Смена пароля завершает все остальные входы.
- Все формы защищены CSRF-токеном.
- Заголовки CSP, `X-Frame-Options`, `no-store` для страниц, внешние скрипты и шрифты не грузятся.
