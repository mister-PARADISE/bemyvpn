# Периметр — памятка для Claude Code

Панель аудита сайтов **по согласию владельца**, в стиле терминала (зелёный на почти чёрном, без свечения и коробок).
Весь интерфейс, сообщения, ошибки и коммиты — по-русски. Владелец проекта общается по-русски: отвечать кратко,
прямо, без преамбул, объяснять понятно.

## Запуск и проверка

- Запуск: `./start.sh` (macOS/Linux) или `start.bat` (Windows) → `http://127.0.0.1:8710`. Данные — в `data/` (в git не идут).
- Тесты: `.venv/bin/python -m pip install pytest pyflakes`, затем `.venv/bin/python -m pytest` и
  `.venv/bin/python -m pyflakes perimeter tests`. Перед каждым коммитом — оба зелёные.
- Тесты не ходят в интернет: `tests/netlab.py` — свой DNS, TCP/HTTP/TLS-сервисы, прокси, поддельные NVD, CISA KEV,
  EPSS, WPVulnerability, endoflife.date; настоящие записи баз — в `tests/data/`. Приложение в тестах — `debug=True`
  (упавший блок страницы роняет тест), `background=False` (расписание не ходит в сеть само).
- Изменил интерфейс — посмотри глазами: запусти панель и сделай скриншот (Playwright), проверь и ширину телефона.

## Устройство

- `perimeter/core/` — ядро: реестры, поля (`fields.py` — одно описание для форм, настроек и параметров модулей),
  настройки, хосты целей (`scope.py`), контракт модулей (`modules.py`), данные модулей (`feeds.py`), загрузчик расширений.
- `perimeter/extensions/` — всё остальное, каждое через `setup(ctx)`: `targets` (цели и хосты), `runs` (движок
  запусков: свой поток и цикл asyncio, цепочки, консоль), `recon` (модули разведки, уязвимости, страница цели),
  `feeds` (обновление данных модулей по расписанию), `proxies`, `catalog` (страница «Модули»), `dashboard`,
  `journal`, `settings_page`. Сломанное расширение откатывается целиком.
- `perimeter/web/` — приложение FastAPI, вход, CSRF, `ui.py` (фильтры шаблонов), `static/app.css`, `static/app.js`.
- README.md — подробное описание для человека; держать в актуальном состоянии.

## Принципы (не нарушать)

- **Один модуль — один вопрос.** Новые возможности — отдельными модулями, не «всё в одном».
- **Пассивный модуль к сайту не обращается** (только DNS и открытые базы). **Активный** ходит только через
  `run.connect` — ядро само отклоняет адреса вне цели, исключённые имена, чужой CDN и непроверенные сети на портах
  кроме 80/443. Не обходить.
- Зависимости модулей — `ModuleSpec.needs`; недостающее и устаревшее движок запускает сам, как make.
- Данные модулей (базы уязвимостей и т. п.) — `ctx.feeds.add(Feed(...))`: обновляются сами; после обновления
  цели перепроверяют **только пассивные** модули. Активные по расписанию не запускаются никогда.
- Ничего не терять: всё найденное — в «Найдено»; на странице цели — сводка, замечания (что плохо и что делать),
  уязвимости, структура. Одна программа — одно замечание.
- Тексты для человека: что не так, почему это плохо и что сделать — по-русски, без жаргона там, где можно.

## Состояние и что дальше

Сделано: цели и хосты, 13 модулей (DNS, сеть, веб, порты, технологии ~110 программ, уязвимости CVE по NVD +
база WordPress + CISA KEV + EPSS, поддержка версий по endoflife.date), самообновление баз, прокси, журнал, настройки.

Дальше по плану: активные модули через свои прокси (вкладка «Прокси» уже проверяет их); WHOIS/RDAP; поддомены из
логов сертификатов; реальный IP за CDN; забытые файлы и открытые админки; уведомления (Telegram); отчёт PDF и
ссылка только для чтения; клиенты и счета — последними, отдельным расширением.

Известное: `start.bat` написан без проверки на Windows; без ключа NVD первая проверка уязвимостей идёт минуты.
